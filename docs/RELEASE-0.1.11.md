# 0.1.11：单向大小快照与共享扫描内存

## 本次处理

已有 AUTO 任务在“单向、仅比较大小、未启用仅更新较新文件”时自动使用目录快照流水线，不改写保存的策略和比较规则。包括开启删除的单向大小镜像任务：比较仍只看大小，删除仍在必要扫描与复制成功之后执行。时间差不会触发额外复制；同大小但不同内容仍按既有大小规则跳过。

也可显式选择新增的“按目录快照仅比较大小”（COMPARE_SIZE）。SHA、双向及 updateOnly 继续使用兼容流程；显式 MIRROR 仍按大小和时间比较，未变更其语义。

源目标各枚举一次当前目录，快照读取 NAME/TYPE/SIZE，不为仅大小比较申请修改时间。在内存或临时快照中比较，匹配文件直接跳过，不再对每个目标文件执行 Path.exists/is_file/stat。实际复制仍会读取源属性以检查变化和保留时间，发布前安全检查不删除。Windows/Linux 的通用实现可能仍需一次必要的属性读取；这些调用与真实网络报文不是一一对应。

大小文件使用原有共享队列。已扫描到大小的大文件独立调度、单线程流式复制；小文件批量入队、批内并行。目录流水线已创建目标目录后，不再为每个文件重复 mkdir。不是将多个文件合成一个 SMB 写入请求，也不是把全部文件加载到内存。

## 快照内存

任务增加 scanMemoryMb，界面为“快照内存预算（MiB）”，默认 256，范围 16–16384。所有扫描线程共享预算。超出预算才将快照转到临时 SQLite，正常结束、失败或回退时释放；仍保留测试用的条目阈值。相较此前每目录 10,000 条即落盘，内存充足时可保留更大的目录快照。

预算按条目名称和对象开销保守估算，不是整个进程 RSS 上限。复制队列、Python 运行时、日志、SQLite 缓存等还需要额外内存。预算在目录组启动时确定，运行中的暂停编辑不修改它。界面展示快照估算占用和落盘数量；运行结果保留峰值估算。

没有持久历史索引，也不依赖上次扫描结果。一个目录仍需枚举完成及冲突校验后开始处理；之后目录扫描与复制并行，不等待整棵树扫描完。

## 对照结果

macOS 本地磁盘，单目录 100,000 文件，两侧大小一致且内容不同，按原有“仅大小”规则应全部跳过。旧版与新版均使用 AUTO、size、文件并发 32、批量 500；新版扫描内存预算 256 MiB。

| 指标 | 0.1.10 | 0.1.11 |
| --- | ---: | ---: |
| 比较总耗时 | 27.559 秒 | 2.762 秒 |
| 文件/秒 | 3,629 | 36,208 |
| 目标文件 Path.stat 调用 | 300,000 | 0 |
| 跳过 / 复制 | 100,000 / 0 | 100,000 / 0 |
| 进程峰值 RSS | 约 77.8 MiB | 约 110.4 MiB |

新版源目标共枚举 200,000 条目，使用本机原生枚举 46 次；估算快照峰值约 202.8 MiB，未发生快照落盘，结束后占用计数归零。

这是单次本地扫描比较基准，未包含实际文件复制和应用日志数据库写入；Path.stat 计数不等于 SMB 请求计数。约 10 倍差异不能直接外推为 Windows NAS 实际复制提速。真实 SMB 仍需实机测试。

原始数据：docs/benchmarks/size-100k-0110.json、size-100k-0111.json。
复现：`python scripts/benchmark_size_snapshot.py --files 100000 --memory-mb 256`；用 `--backend` 指向旧版 backend 可对照。

## 验证及升级

156 项 Python 测试通过，覆盖大小相同但时间不同、不逐文件查询目标、共享预算落盘释放、大小混合复制和大小镜像删除。浏览器回归覆盖新策略、预算输入和原有真实同步流程。

配置协议升至 4，避免旧后台忽略内存配置。停止旧程序后解压新包，沿用固定数据库目录与 Python 设置启动，再刷新网页。任务表仍保存 JSON 配置，不需要手工修改 SQLite 表结构，已有任务日志保留。

运行前可根据可用内存提高快照预算，例如 1024 或 2048 MiB；不建议不留余量地占满物理内存。线程上限仍为 32，本次主要收益来自减少逐文件查询和不必要落盘。异步日志、Windows 原生复制等后续方向本次未实施。
