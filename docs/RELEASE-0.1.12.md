# 0.1.12：发布阶段诊断与重复请求减少

## 针对实际现象

0.1.11 的“检查路径并发布文件”还包含发布后的临时文件清理及日志等待；复制前路径检查尚未计入活动文件。因此“活动 12 / 上限 32、11 个处于发布阶段”不能证明只有 12 个 worker 工作，也不能单凭该标签断定 NAS 重命名耗时。

本版将复制前检查纳入状态，区分创建临时文件、打开、读写、强制刷新、源变化和长度复核、权限时间、等待文件锁、源根复核、目标路径复核、原子发布、清理、日志等待及文件重试。记录各阶段累计线程秒数、次数、最大单次耗时，界面显示累计最耗时的四个阶段。累计线程时间不是墙钟时间；同一文件可能多次进入某阶段。

## 性能诊断日志及导出

在任务“性能与重试”中勾选“性能诊断日志”，保存后执行；新版运行中的任务也可以先暂停、开启后保存恢复。默认关闭诊断日志写入，基本阶段计时仍保持有界。

- 有文件事件时，每 10 秒最多记录一条 `performance_debug` 汇总，并在成功结束时输出最终汇总；所有线程卡在系统调用时，不承诺持续写出周期日志。
- 汇总包含阶段累计耗时、次数、最大耗时、活动文件、完成计数、扫描指标及慢文件抽样。
- 文件处理阶段累计达到 1 秒才进入慢文件候选，每 10 秒最多采样 5 个，缓冲也最多 5 个；包含路径及阶段耗时。它是抽样，不是完整慢文件清单。
- 使用原有 SQLite 日志存储和索引，不逐步骤向终端打印，不增加每文件一次数据库提交。
- 日志页选择“性能诊断”筛选，展开“查看性能诊断 JSON”。
- 点击“导出性能诊断”，下载 `file-sync-run-<id>-diagnostics.json`。包含版本、Python/系统版本、任务配置、实时或最终进度，以及最近 20 条已落库诊断汇总。即使周期日志尚未写出，也能导出当前活动阶段。文件中含源目标目录及文件路径，不包含文件内容，不会自动上传。
- 对应只读接口：`GET /api/runs/{run_id}/diagnostics`。

建议运行 2–5 分钟后导出一次；若长时间停住，在停住时再导出一次。重点对比 `path_check`、`flushing`、`metadata`、`source_check`、`target_check`、`renaming`、`logging` 的阶段总耗时、最大值，以及当前活动阶段停留秒数。

## 减少重复请求

Windows 将符号链接和目录联接检查合并为一次不跟随链接的属性读取。根目录类型判断复用已取得的 stat 结果；移除复制前紧邻重复执行的目标路径链检查；成功 os.replace 后不再向不存在的临时路径发送 unlink。失败和硬链接不覆盖发布的临时文件仍会清理。

每个文件发布前仍复核根目录身份和目标路径，没有添加跨文件安全检查缓存或定时跳过检查，也未取消 fsync、修改时间校验、原子发布和删除保护。真实 Windows SMB 性能收益尚未测量，不能据此承诺复制速率。

## 验证与升级

161 项 Python 测试通过，包含成功发布不再删除不存在的临时路径、失败清理、Windows 联接识别单次查询、诊断落库/筛选/导出以及计时和采样有界验证。浏览器回归验证暂停开启诊断和下载 JSON；发布包检查隔离启动及新增测试。

版本 0.1.12，配置协议 5。先正常停止旧程序，再解压新包，沿用固定数据库目录和 Python 配置启动。旧进程不能热更新。任务定义和已复制文件保留，但不承诺跨进程保存扫描游标；重新运行时按所选策略比较，COPY_ALL 会再次覆盖，不能将它当作增量续传。
