# 0.1.13：降低 Windows 路径安全检查成本

## 诊断与决策

用户提供的 0.1.12 Windows SMB 运行诊断显示：约 4899 秒复制 90924 个文件、跳过 49910 个，失败为零；实际复制约 18.56 文件/秒。复制前路径检查与发布前目标检查占累计线程时间约 87.8%，每文件平均合计约 1.51 秒。32 个工作线程已充分工作，锁等待接近零，快照没有落盘。增加扫描线程、内存或异步日志不是本轮重点。

采用轻量属性查询与重复操作消除；暂不采用祖先目录 TTL 缓存，也不引入未经 Windows SMB 验证的持久目录句柄。后两者需要单独处理目录替换、重解析点和共享访问语义，不能以减少检查为由弱化现有安全行为。

## 修改

- Windows 检查普通路径时用 `GetFileAttributesW` 判断是否存在重解析点，避免获取不需要的完整文件身份、时间和大小。
- 有重解析点时仍以 `lstat()` 区分符号链接、junction 和原本允许的其他类型；原生查询失败时回退原有 `lstat()`，共享根、长路径、权限和网络错误不会被直接当作安全路径。
- 目标根目录的同一次 `lstat()` 同时提供链接信息和文件身份，避免先查链接再查身份。
- 每次复制前和发布前均检查，没有跨文件安全结果缓存；macOS/Linux 保留既有路径检查。
- 不覆盖发布区分“重命名消耗临时名称”和“硬链接仍保留临时名称”，成功重命名后不再做无效删除；硬链接回退、已存在和失败仍清理临时文件。
- 所有同步策略、原子发布、刷盘、时间保留、删除保护保持原有语义。

参考：[Microsoft GetFileAttributesW 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileattributesw)。该 API 返回链接自身属性，支持 SMB；共享根可能失败，不能移除回退路径。

## 新诊断字段

导出的 `progress.pathCheckMetrics` 和周期诊断汇总新增以下累计计数，仅覆盖目标路径安全检查（含删除前检查），不是全进程/整个复制流程的 metadata 总数，也不是实际 SMB 网络包计数：

- `targetChecks`：检查目标路径链的次数。
- `attributeQueries`：轻量原生属性查询次数。
- `attributeFallbacks`：因重解析点或原生失败进入完整查询的次数。
- `lstatQueries`：Windows 完整不跟随链接查询次数。
- `rootIdentityQueries`：根目录身份核验查询次数；Windows 下它是 lstatQueries 的子集，不能相加当总数。
- `portableLinkChecks`：macOS/Linux 路径链接检查次数。

固定大小计数字典，每轮路径检查后一次汇总，不新增逐路径日志或数据库事务。扫描器的 `metadataCalls` 仍仅表示扫描器查询。

## 验证与性能边界

本机 168 项回归测试，167 项通过、1 项原生 Windows 测试跳过；隔离启动冒烟通过。新增覆盖普通属性不读取完整 stat、重解析点分类、异常回退、目标根目录替换、重命名不清理、硬链接仍清理、诊断计数。Windows 原生用例加入 CI。

逻辑查询验证：普通 Windows 路径从一次完整 lstat 改成一次轻量属性查询；目标根目录从两次查询合并为一次；重命名成功后删除不存在临时文件的次数从一次变为零。**没有 Windows NAS 环境实测，不能宣称吞吐提升倍数。** 目录链仍逐文件检查；若轻量查询依然昂贵，再依据新日志评估句柄保护方案。

提供只读基准，不写入目标、不递归扫描：

```cmd
E:\python\python.exe scripts\benchmark_path_checks.py "\\NAS\share\含文件的子目录" --samples 100 --rounds 4 > path-benchmark.json
```

对同一批目录项及其父路径交替执行旧 lstat 和新属性检查，输出耗时和查询次数。测试顺序、系统缓存和 NAS 负载会影响结果；该基准只比较链接检查，不代替真实同步吞吐测试。新任务运行 5–10 分钟后导出性能诊断，对比 path_check/target_check 的每次平均耗时和实际 copied 增量。

## 升级

版本 0.1.13，配置协议仍为 5，无数据库迁移。正常停止旧程序，解压新包并沿用固定数据库目录和 Python 路径后启动；运行中的旧进程不会热更新。保留任务定义，不承诺跨进程保留扫描游标。
