# 0.1.18：减少复制与时间保留中的重复远程操作

## 修改范围

按现有第 21 次诊断及代码检查，继续优化复制后的属性处理，不调整并发、不要求用户追加性能对比实验，也不改变根目录身份查询策略。

原流程每个临时文件执行三次完整 stat：长度检查、元数据阶段再次读取、写入时间后读回。新版正常路径保留长度检查和最终时间读回两次，移除中间的重复读取。

Windows 两次读取改为 GetFileAttributesExW，一次只取得长度、时间等基本属性，不为临时文件校验额外读取 inode 等身份。它不是新增的扫描或历史索引。100ns FILETIME 使用整数换算到 Unix 纳秒，长度使用完整高低 DWORD 拼接，支持大于 4GiB 的文件。

接口不支持、权限/共享兼容性异常时该目录组切换回 Python stat，不重复尝试；少量已在途调用可能各完成一次。网络与路径错误继续沿现有流程处理，不能当作成功。重解析点回到原 stat 行为。

轻量查询得到异常长度或超出容差的修改时间时，先用完整 stat 复核，再决定是否报错，避免因属性缓存误判。每次仍读取当前结果，不保存跨文件属性缓存。

## 时间与发布语义

- 保留源时间：仍使用复制前源访问/修改时间写入，并读回修改时间检查容差。
- 不保留源时间：保留文件实际写入的时间，不再将当前时间原样写回一次。报告仍读取实际修改时间；哈希读取可能更新访问时间，与原流程一致。
- 权限复制、源文件变化检测、长度检查、SHA 校验、fsync、临时文件原子发布和删除保护保留。
- 未直接取消刷盘或时间校验，也未为加速移除安全检查。

## 验证

使用既有 201 项回归：本机 197 项通过，4 项原生 Windows 测试跳过。另在本机检查原生结构 36 字节布局、超过 4GiB 的长度转换、100ns 时间精度，以及接口不支持时仅尝试一次后回退。没有增加用户侧测试任务。

使用相同 10 个临时文件，直接对照 0.1.17 引擎与新版引擎，统计调用而非宣称 NAS 提速：

| 模式 | 0.1.17 完整属性读取 | 新版 macOS 完整属性读取 | 时间写回旧→新 |
|---|---:|---:|---:|
| 保留源时间 | 30 | 20 | 10→10 |
| 保留写入时间 | 30 | 20 | 10→0 |

Windows 正常路径的两次读取进一步改为轻量接口；兼容性/校验异常仍可能使用完整查询。以上是显式调用量对照，不是 SMB 数据包数量，也不是实际 NAS 吞吐承诺。

## 发布

0.1.18，配置协议仍为 5，无数据库迁移。正常停止旧进程后换新包，沿用数据库目录及 Python 配置。现有任务和比较规则不变。

接口依据：[Microsoft GetFileAttributesExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileattributesexw)、[WIN32_FILE_ATTRIBUTE_DATA](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-win32_file_attribute_data)。
